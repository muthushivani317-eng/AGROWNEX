# Controlled-beta release blockers and rollback

## Internal testing

Requires configured Gemini credentials, one backend worker or a shared receipt store, controlled tester roles, complete green suites, and real-provider smoke validation.

## Pilot testing

Requires shared durable confirmation state, reviewed Tamil UI, production-like security review, real Android E2E evidence, field test protocol, privacy review (verify against official DPDP requirements), and crop/runtime-specific approval.

## General farmer release

Blocked. It additionally requires defensible dedicated crop-ID evidence or approved temporary-provider release evidence, sealed Tamil Nadu field evaluation, monitoring/rollback, and explicit safety approval.

## Rollback

Remove the crop-identification router registration or disable the controlled role assignment. Disease endpoints will continue to reject requests lacking valid confirmation receipts. Do not weaken receipt validation, model abstention, or role guards during rollback.
